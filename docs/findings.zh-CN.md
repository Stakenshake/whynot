## 三条站得住的发现

### 1. 模型不把年龄当信号

30 天前写的决策和 7 年前写的，被遵循的比例**一模一样**——两个模型、60 次运行，零偏差。把过期的那条藏起来，行为完全回到基线。

**含义：** 让 agent「对旧笔记保持怀疑」，等于让它权衡一个它没有的量。过期必须是结构性的。

→ [e4-dose-response.md](e4-dose-response.md)

### 2. 记录一条否决，会实质改变答案

三个模型家族、n=20 合并：Redis 那条从 52/60 → 0/60，TypeScript 那条从 60/60 → 13/60。两者 p < 0.0001。

**含义：** 核心机制是真实且显著的。

→ [e3-power.md](e3-power.md)

### 3. 写的理由比日期更重要

同一个标题、同样的年龄，两种理由：

| 记录里的理由 | 读起来像 | 抵抗率 |
|---|---|---|
| 「团队没人会 TS」 | 一个**会变的条件** | **13/60（22%）** |
| 「这个项目字段变更频繁」 | 一个**项目属性** | **0/60** |

抵抗的回复直接攻击前提：*「那个条件现在很可能已经不成立了。」*

**含义，而且反直觉：** 命名了**「条件」**的理由比陈述了**「属性」**的更安全，因为它邀请模型去复核。通常「写持久理由」的建议，对这个工具是反的。

→ [e3-power.md](e3-power.md)、[e4-dose-response.md](e4-dose-response.md)

## 最重要的限定

**E1 表明效应不是普遍的。**

有真实代码、没有记录时，GPT 已经在 12/12 的运行为仓库现有的技术选型；加上记录没有任何变化。DeepSeek 面对同样的代码，在 10/12 的运行为仍然倾向于被否决的方案，直到记录拦住它。

所以诚实的主张不是「agent 会盲从陈旧决策」，而是：

> 一条记录是否起作用，取决于模型是否使用代码。**代码编码了「选了什么」；仓库里没有任何东西编码「否决了什么」。记录对第二类最有价值。**

→ [e1-code-context.md](e1-code-context.md)

## 还没有测的东西

| 缺口 | 为什么重要 |
|---|---|
| **真实使用中的价值（E6）** | 用户唯一关心的数字。没测。这个项目不声称它。 |
| 模糊回复（E0） | 判分校准用的是几乎全部清晰的案例。 |
| 带上下文压缩的长会话 | E5 最多两轮。 |
| Claude / Gemini / 更大的 DeepSeek | E3 用的是 Haiku 和 DeepSeek Flash。 |
| 有很多条决策的仓库 | 所有实验只用了 1–2 条。累积干扰未测。 |
| 大规模误用 | E2 只测了一条不相关决策。 |
